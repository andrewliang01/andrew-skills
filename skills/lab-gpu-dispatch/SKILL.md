# Andrew 的 GPU 资源与任务

## 查看资源

| 主机 | SSH 别名 | 已核验硬件 |
| --- | --- | --- |
| g130-40 | `andrew@g130-40` | 8 × RTX 4090 |
| g130-51 | `andrew@g130-51` | 2 × RTX 5090 |
| g130-35 | `andrew@g130-35` | 2 × RTX 4090 |
| 本机 | 直接查询 | 1 × RTX 5090 |

- Ubuntu 当前工作站可点击桌面或左侧 Dock 的「个人 GPU 看板」。服务运行时可打开 [本机看板](http://127.0.0.1:8765)。它通过 NVIDIA 驱动显示 GPU 利用率、显存、温度与计算进程，页面打开时每 15 秒采样。
- 先用现有 SSH 配置和本机 `nvidia-smi` 查询。核对别名、账号和主机指纹。g130-35 的内网地址从本机配置获取。g130-40 和 g130-51 已验证现有 SSH 密钥可用。g130-35 无可用密钥时让用户在终端隐藏输入密码。凭据只在本机认证流程中使用。
- 若需另装或恢复看板，使用随技能提供的 [看板源码](assets/gpu-monitor/server.py)。从技能根目录运行：

  ```bash
  python3 assets/gpu-monitor/server.py --password-35
  ```

  需要 Python 3.9+、SSH、`nvidia-smi`；g130-35 的密码模式还需要 `sshpass`。已有该节点的密钥时省略 `--password-35`。若系统没有 g130-35 别名，可在启动进程的环境里用 `GPU_MONITOR_G130_35_HOST` 指定已核验的地址或别名。服务只监听回环地址，默认端口 8765，端口冲突时用 `--port`。GNOME 和 Edge 下可运行 `bash assets/gpu-monitor/launch-desktop.sh`，启动器会复用已经运行的看板或打开终端提示。
- “低占用”表示无可见计算进程、GPU 利用率 ≤ 5%、显存占用 ≤ 512 MiB。用它初筛，再确认平台预留、CPU、主机内存和镜像兼容性。采样失败或占用未知时保留未知状态。静态硬件清单不能代替实时采样。

## 通过 lab-platform 分发任务

查看资源和打开看板仅执行只读采样。在用户要求提交任务时，先从当前工程配置、文档或用户授权的连接中核验 Andrew 可用的 lab-platform 实例、API 地址、平台主机 ID 和资源准入。当前个人看板没有接入此平台。缺少该实例或访问权限时汇报具体缺项。

1. 使用已确认的 `lab` CLI 查询主机、GPU 和活动任务，或用 [资源查询脚本](scripts/pool_status.py) 读取资源与预留。脚本使用 `LAB_URL` 和已配置的 `LAB_TOKEN_FILE` 或 `LAB_PLATFORM_DIR`。可用 `--refresh` 刷新监控探针，用 `--host` 指定平台主机 ID。只选择在线、非维护、采样新鲜、Docker 可用、占用已知且空闲、无未结束任务预留的候选卡。按任务核验 CPU、内存、显存与驱动。
2. 按 [任务规格与兼容性](references/task-spec.md) 准备镜像、代码和资产。固定镜像 digest，核验 CUDA、GPU 架构、驱动和关键源码补丁。新组合先做一次代表性短测。代码与资产使用允许目录下的版本化快照。继承实验的记录器、日志、检查点频率和回传路径。
3. 提交前再次核对资源。将任务文件与任务记录保存在当前工程，记录任务用途、主机、GPU UUID、镜像 digest、资产 ID、任务 ID、提交时间和输出位置。平台返回 `RUNNING` 且日志显示真实计算进展，才报告已运行。
4. 独立任务可在多张空闲卡并行。按实际任务需求限制并发和等待预算。同一卡逐个执行，多卡训练需要程序支持。仅明确未受理的资源竞争可刷新后重试；提交超时先查已登记任务，避免重复投递。仅取消本次授权的任务。
5. 按约定回传并核验文件。平台的训练状态和结果同步状态分别核对。结果同步失败重试传输，保留任务 ID 和远端产物以便恢复。
